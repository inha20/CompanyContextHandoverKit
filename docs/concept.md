# 개념 설계

## 문제
기업이 LLM을 업무에 쓸 때 가장 흔한 실패는 모델 성능이 아니라 **맥락 부족**입니다.

- 회사의 현재 상황, 용어, 규칙을 모른 채 그럴듯한 답을 만든다.
- 매 대화마다 사람이 같은 배경 설명을 반복한다.
- 담당자가 바뀌면 AI에게 가르친 내용이 사라진다.
- 맥락이 낡아도 아무도 모른다.

## 아이디어
> 폐쇄형 AI에 프롬프트를 적당히 주어 초기 학습을 마치고, 그 내용을 **인수인계 폴더**에 저장해 참고·관리한다.

모델을 재학습하지 않습니다. 맥락은 모델 안이 아니라 **사람이 읽고 고칠 수 있는 파일**에 둡니다.

```
인수인계 폴더 (Single Source of Truth)
   │  build
   ▼
컨텍스트 팩 ──► 온보딩 프롬프트 ──► LLM이 이해 확인 / 공백 보고
                                       │
   업무 지시 (맥락 유지) ◄──────────────┘
                                       │
   세션 종료 → 갱신 제안 → 사람 검토 → 폴더 반영 → check / log
```

## 설계 원칙
1. **파일이 진실이다.** 대화 기록이 아니라 폴더가 기준이다.
2. **변동성에 따라 분리한다.** 거의 안 변하는 것(01), 자주 변하는 것(02, 06)을 나눠 낡음을 추적한다.
3. **모르면 모른다고 한다.** 문서에 없는 내용은 추측하지 않는다.
4. **사람이 반영한다.** AI는 갱신안을 제안만 하고, 승인은 사람이 한다.
5. **이식 가능하다.** 순수 마크다운이라 어떤 모델·도구에서도 쓴다.

## 폴더 구성과 변동성
| 파일 | 내용 | 변동성 | 낡음 검사 |
|---|---|---|---|
| 01 회사 프로필 | 사업, 제품, 어투 | 낮음 | – |
| 02 현재 상황 | 목표, 이슈, 변화 | 높음 | O |
| 03 용어집 | 약어, 코드명 | 중간 | – |
| 04 규칙과 제약 | 금지·승인 필요 | 낮음 | – |
| 05 사람과 역할 | 담당 구조 | 중간 | – |
| 06 진행 업무 | 상태, 다음 행동 | 높음 | O |
| 07 의사결정 | 결정과 이유 | 누적 | – |
| 08 변경 이력 | 갱신 기록 | 누적 | – |

## 한계와 주의
- 컨텍스트 창 크기를 넘으면 팩을 분할하거나 요약해야 한다(`build`는 토큰 추정치만 보여 준다).
- 인수인계 폴더에는 영업비밀이 들어갈 수 있으므로 공개 저장소에 올리지 않는다(`.gitignore` 참고).
- 토큰 추정은 근사값이다.
